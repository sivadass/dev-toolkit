# Base64 Encoder/Decoder — Design Spec

**Date:** 2026-08-07  
**Status:** Approved for implementation  
**Scope:** Client-side text Base64 encode/decode tool.

## Goal

Add a **Base64** tool so users can encode and decode text strings entirely in the browser. Files never leave the device. Replaces the existing coming-soon stub at `/tools/base64`.

## Product decisions

| Decision | Choice |
|----------|--------|
| Input | Text strings only |
| UI mode | Encode / Decode via horizontal MenuList tabs |
| Convert | On demand (PageHeader primary CTA) |
| Encode alphabet | Standard (`+/`) by default; optional URL-safe Toggle (`-_`) |
| Decode | Auto-detect standard + URL-safe; strip whitespace; fix padding |
| Unicode | UTF-8 via TextEncoder / TextDecoder |

## Out of scope

- File upload / download
- Live-as-you-type conversion
- Web Workers
- Data-URI prefix helpers
- Separate URL-safe encode alphabet without the Toggle

## UX

1. **PageHeader** — “Base64” / on-device privacy subtitle. Primary CTA: Encode or Decode (by active tab); disabled when input is empty.
2. **Tabs** — CleanPlate `MenuList` with `direction="horizontal"`; items Encode / Decode; panel content swaps below.
3. **Encode panel** — Plain-text input → Base64 output after CTA. Optional **URL-safe** `FormControls.Toggle`.
4. **Decode panel** — Base64 input → plain-text output after CTA. No variant toggle; accepts standard and URL-safe.
5. **Actions** — Clear (active tab); Copy output with brief “Copied” feedback. Switching tabs preserves each tab’s last input/output independently.
6. **Errors** — `Alert` on invalid Base64 decode.

## Architecture

```
UI (base64-page)
  → useBase64 (mode, per-tab drafts, urlSafe, convert/clear/copy)
  → encode-base64 / decode-base64 (pure UTF-8 helpers)
```

### Module layout

```
app/src/features/base64/
  encode-base64.ts

  *.test.ts(x)
```
